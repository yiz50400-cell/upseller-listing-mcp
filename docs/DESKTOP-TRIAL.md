# 自动上架试用版（风格 B，Windows / Mac）

客户打开软件即可填写并走预览 / 保存草稿。不需要安装 Cursor，也不需要安装 Codex，也不用先装 Node。任务表不再是唯一入口。

## 怎么打开

### Windows

1. 使用 64 位便携版：`UpSeller-Listing-Trial-0.3.11-trial-win-x64.exe`（或 GitHub Actions 产物同名文件）。**本轮 Windows exe 尚未打入交付目录，不能当作已交付。**
2. 双击运行。无需安装。未签名时 Windows 可能提示 SmartScreen，选择「仍要运行」即可。

### Mac（Apple Silicon 优先，也可出 Intel 包）

1. 使用对应芯片的磁盘映像，例如 Apple Silicon：`UpSeller-Listing-Trial-0.3.11-trial-mac-arm64.dmg`（Intel 为 `...-mac-x64.dmg`）。同名 `.zip` 里是可以直接拷走的 `自动上架.app`。
2. 双击打开 `.dmg`，把自动上架拖到「应用程序」或直接从映像里打开。打开前请先退出正在运行的 0.3.10（或 0.3.7 / 0.3.8 / 0.3.9）。
3. 试用包未做 Apple 开发者签名。若提示「无法打开，因为无法验证开发者」：按住 Control 再单击图标，选择「打开」，或到「系统设置 → 隐私与安全性」里点「仍要打开」。
4. 若提示「已损坏，不能打开」：这是未签名应用被隔离，不是文件真的坏了。在「终端」执行（把路径换成实际位置）：
   `xattr -cr "/Applications/自动上架.app"`
   然后再打开。

### 登录与上架（Windows / Mac 相同）

1. 若还没有登录：打开左侧「设置」，状态会显示「已登录 Upseller」或「未登录」。未登录时点「登录 Upseller」，已登录时可以「重新登录」，也可以点「退出登录」后再换一个账号。退出会清掉本机应用目录里的登录状态，不会动 Documents 里的登录文件，界面也不会显示账号内容。软件会弹出登录窗口（使用软件自带的浏览器，不必先装 Node，也不用执行 `npx playwright install`）。登录是否有效会做一次轻量校验，不只看本地文件长度。
2. 在「任务」页勾选产品，填写目标店铺、复制到几店、价格、标题和图片。登录后点「从草稿箱选择」或「复制在线商品」，会打开带商品原图（接口有图时）、完整标题、店铺和价格的列表，可搜索标题或编号，也可按店筛选。没有图片时才显示「图」占位。选中草稿会载入标题、价格、货币、店铺和草稿编号；选中在线商品会把该产品编号复制到当前目标店，以便改图改价后上架成新草稿或新商品。两条入口互不混用。按编号手填只是备用办法，草稿编号旁的「载入」只载入草稿。先「预览」，再用主按钮「保存草稿」。
3. 「发布」不是默认操作，会弹出二次确认。发布成功后的提示只显示「已提交发布请求」，任务列表状态会显示「已提交」。示意商品显示为「示例」，不能预览或上架，请先添加真实产品并填写产品ID。
4. 侧栏只有「任务」和「设置」。请先退出旧版（包括仍挂着的 0.3.0–0.3.10 安装盘），只打开本页写明的 0.3.11-trial 包。请先退出仍在运行的 0.3.10、0.3.9、0.3.8、0.3.7 或更早版本。

源码开发调试（本仓库根目录已 `npm install`，并在 `desktop/` 安装 Electron）：

```bash
cd desktop
npm start
```

Windows 便携版：`cd desktop && npm run build:win`  
Mac 包（需在 macOS 上构建）：`cd desktop && npm run build:mac`（仅 Apple Silicon）或 `npm run build:mac:all`（arm64 + Intel）。

## 做了哪些

- 深色工作台界面（近黑背景、低对比分隔、单一靛蓝强调色），左侧导航为任务 / 设置；上方任务列表，下方编辑表单。界面去掉了标语和说明段落，用「从草稿箱选择」和「复制在线商品」两个分开的入口把操作放在控件里。
- 「从草稿箱选择」打开草稿列表窗（接口有图时显示商品原图，否则才用「图」占位；完整标题、店铺、价格，可搜索、可按店筛选）。点选一条即走现有载入草稿路径，并自动带出标题、价格、货币、shopId/shopName/站点、draftId。未发布草稿如果没有在线产品编号，会清掉表单里上一份留下的产品编号。
- 「复制在线商品」是另一套只读在线商品列表（同一接口，状态不是草稿），同样在有图时显示商品原图。选中后把该产品编号复制到当前目标店，不走载入草稿。之后可改图改价，再保存成新草稿或新商品。
- 一行若已成功保存过草稿 A，再选草稿或在线商品 B 时，会自动换新的任务编号（同一行可见），不再出现「任务 ID 已用于不同内容」。未保存过的新行直接绑定并载入，也不会残留上一份草稿的显示名。再点同一项仍会重新载入。
- 按编号手填仍可用，但不再暗示在线产品编号可以用「载入草稿」。
- 软件内直接填写产品ID、复制到几店、价格、标题、主图 / 附图 / SKU图、视频。
- 预览、保存草稿复用现有 `upseller_run_listing` / `upseller_run_batch`；固定每批 8 个。
- 同一任务行的 taskId 在同一份未发布草稿上保持稳定。先「保存草稿」再「发布」，或改价/改标题后再保存、发布，只要回执对应同一份未发布草稿，就会更新内容指纹并继续，而不会把 `publish` 当成内容变更，也不会卡在 already-completed。已经发布或已上线的商品不会盲目再发。
- 发布成功后的提示只显示「已提交发布请求」。同一行在任务列表里的状态改为绿色点加「已提交」，不再显示「待发布」。尚未发布、只保存为草稿、已发布或其他状态都不会改成「已提交」。预览完成提示仍是「预览完成，没有写入草稿，也没有发布」；保存草稿成功仍是「已请求保存草稿，不会发布」。这些提示都不会出现「试用版」「不宣称」「平台正在处理」或「真机刊登」这类补充。失败时界面会显示具体原因，不再一律变成「操作没完成，请再试一次。」若仍遇到内容冲突，也不会把「任务 ID」这种话直接显示给用户。
- 登录复用 `upseller_login` 的会话写入方式，但试用包用软件自带的登录窗口，不再依赖本机 Playwright 缓存。会话写入本机用户目录下的 `mcp/.env`，界面只显示「已登录 Upseller」或「未登录」。登录状态会向 Upseller 做一次轻量校验。
- 示意商品显示为「示例」，不能预览或上架。空店铺列表不会再塞入示意店名。
- 载入已有草稿后，改价或改标题再保存、发布，只会针对下拉框里选中的那一家店；不会把同一份草稿复制到多家店。
- 载入草稿后会同时写入该草稿的店铺编号和名称，并自动把目标店下拉框改到草稿所在的店，不会沿用载入前选中的店。
- 页脚的任务名过长时会截断并显示省略号，不会叠到「预览 / 保存草稿 / 发布」按钮上。载入后标题输入框会从开头显示。
- 任务列表里的长标题会在产品名列内截断并显示省略号，不会叠到目标店、价格、状态和删除按钮上。

## 未完成项 / 限制

- 视频栏是选填。这一版还不能传视频，填了也不会发出去；视频只会保存在本机，不会进入预览 / 草稿 / 发布流程。
- 未做代码签名。尚未做实机上架验收，不能声称真机刊登已过。
- Windows / Mac 安装包不要提交进仓；用 GitHub Actions 产物或本机 `desktop/dist/`。
- 本轮 Windows exe 不在交付目录中，不能写成已交付。


任务列表有清楚的「添加产品」按钮，可新增一行再填写信息。列表里的产品（包括示意示例）都可以单条删除或删除所选，删掉后不会再自动出现。
